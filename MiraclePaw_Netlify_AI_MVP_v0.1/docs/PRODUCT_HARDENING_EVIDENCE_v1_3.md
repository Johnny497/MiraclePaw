### 修正所依賴嘅假設

1. Mock 測試模擬上游 HTTP 結果，**唔會**打真實 OpenAI API，唔會證明帳戶模型存取或配額。
2. 超時分類依賴底層 fetch 丟出 `AbortError`；其它網絡錯誤仍一律安全退回 `AI_UNAVAILABLE`。
3. `looksLikeCrisis` 使用保守關鍵字匹配，亦可能有誤判；只係更小風險嘅額外守門，唔係有保證嘅安全控制。
4. 沒有增加任何後台資料庫、監察面板或自動向 NGO/家長傳送對話。
5. 所有錯誤只輸出錯誤分類，不主動記錄原始訊息；但仍需核查 Netlify 與 OpenAI 平台及供應商自身的日志／留存政策。

## 3. 工程驗收步驟（不需充值 API）

在現有 GitHub Repo 的應用資料夾 `MiraclePaw_Netlify_AI_MVP_v0.1/`：

```bash
npm test
```

具體 Mock 情景：
1. 有效密碼、一般聊天：Mock moderation → Mock Responses，正常回應，仍用 `store:false`。
2. 錯誤／缺失密碼、惡意角色歷史、非 POST、過大內容：在模型呼叫前拒絕。
3. 模擬 Moderation 503／回應格式不完整：**不會**交由未審查模型生成支援回應。
4. 模擬 Moderation 429／Responses 429：只請求一次上游 endpoint，返回 `AI_LIMIT`；頁面提供固定劇本。
5. 模擬 AbortError：返回 `AI_TIMEOUT`，不重試。
6. 模型輸出含危機關鍵字：不直接呈現原輸出，改用固定支援資源；一般回覆不增加額外 Moderation 呼叫。
7. 主頁「今日唔想出門」：有無輸入試玩密碼，都不發出網絡請求，仍提供不懲罰陪伴。
8. 網絡錯誤：顯示 AI 暫時不可用，明確連往五個預設虛構劇本；重新開始後清除錯誤通知。

完整測試通過、Netlify Preview 成功，只可支持 **程式邏輯與部署預覽**，唔代表真實服務／未成年可用。
