# Phase 5E-3 — Global quota candidate (offline only)

Baseline: Draft PR #16 `951b3524f32cd0f41f9d8200d0d15266ca556ea2`. This candidate does not authorize AI activation, database provisioning, credentials, environment changes, production changes, or merge.

## Bound and scope
- One shared, manually provisioned singleton D1 row for both routes in this exact private PR #16 preview. Every non-local AI pipeline irrevocably reserves one admission and HK$1 (100 integer HKD cents) before the first moderation request. 20 admissions and HK$20 reserved total; at most 20 generation attempts, 40 moderation attempts (60 provider calls total). Local keyword crisis support, unauthorized/invalid requests, and free static companionship use no quota. No retries, refunds, or automatic creation, extension or renewal; if a reservation committed but its response was lost, the admission stays consumed.
- The database UTC time enforces a maximum 30-minute approved window. Require a remaining 65 seconds for chat or 41 seconds for sandbox before reservation; check lease and enable flags before each provider call. In-flight requests already sent may still be processed after abort/expiry. Retain the existing per-IP/domain edge limits, request limits and 20s/12s upstream timeouts. Add serialized body caps (chat generation 36,000 bytes, chat moderation 64,000 bytes, sandbox 8,192 bytes) and 1,600 UTF-16-code-unit maximum reviewed output. Generation output limits remain 420/250 tokens. No provider HTTP redirects. Pin configured chat model to gpt-5.4-mini; any other explicit override fails closed. Sandbox retains deepseek-chat. Aliases may change provider-side; review applicable exact model/pricing first.
- HK$1 is a provisional conservative reservation, **not a confirmed cost upper bound or actual billing amount**. Before enabling, independently calculate each route's worst-case generation input/output cost, two moderation calls (including full context), reasoning token rules, model availability/alias changes, FX/taxes and other costs; prove the HK$1 allocation adequate or revise the policy and retest. Use separate provider projects/keys and actual provider-enforced spend controls where available. D1/Netlify charges, rejected quota transactions, other deployments, unrelated use of the keys, and the historic local CLI are not covered by this ledger. Do not run the historical local CLI or any other live provider flow during the window. No automatic recurring window; fresh approval required for any new window. Two adult fictional-data testers is an operational restriction, not an enforced two-person identity limit.

## Proposed storage and configuration (not provisioned)
Cloudflare D1 candidate, using parameterized query REST API:
https://developers.cloudflare.com/api/resources/d1/subresources/database/methods/query/
https://developers.cloudflare.com/d1/best-practices/query-d1/
`netlify/quota/schema.sql` creates a singleton table with no data. `netlify/lib/quota.mjs` issues one conditional UPDATE ... RETURNING (not a racy read then write). Both routes must point to the same dedicated database and same operator-created window row; never use separate counters, DBs, automatic resets or local fallback for admission. The row stores only opaque window ID, policy, timestamps and integer counters, not messages, personal identity, IP, passcodes or AI credentials. Service access logs/retention still need review.

Configuration is default-deny: existing route flags and global kill switch must explicitly permit, plus `CONTEXT=deploy-preview` at function runtime, exact PR #16 Preview host, `AI_QUOTA_ENABLED=true`, `AI_QUOTA_PRICE_REVIEWED=phase5e3-v1`, and server-only D1 account/database/token/window identifiers. Do not set these variables now. The review flag is an operator attestation, not automatic price verification. Confirm runtime context and request URL semantics on Netlify (missing or different values block). A hostname check is not identity authentication. Verify alternate URLs, private access gates and credential scope separately. Use a dedicated isolated account/project because D1 write credentials may have broader authority than the ledger row; verify least privilege and provider access/retention before provisioning. Never expose tokens client-side or commit them. Missing, malformed or ambiguous D1 replies, mismatched windows, exhausted quota, outage and timeout fail closed, with existing free fallback; D1 has a 4s request timeout, no application retry. No frontend or deployment settings changed.
